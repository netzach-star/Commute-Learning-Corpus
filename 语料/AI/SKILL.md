# AI 语料规则

先遵循项目根目录 `SKILL.md`，再应用本文件。

## 1. 动态学习画像

最后整理：2026-07-22。以下状态随学习推进更新。

### 已确认基础

- 熟悉 NumPy 数组、维度和矩阵运算；
- 有较成熟的 Agent 开发与 AI 工具使用经验；
- 熟悉从 API 层调用大模型，并能围绕工具、提示和项目需求完成实际开发。

### 当前不应默认

- 对 LLM 内部原理的系统理解；
- 张量的严格对象与形状语义；
- Softmax、交叉熵、注意力和反向传播；
- 从训练数据、优化目标到完整 GPT 训练与推理的依赖链。

Agent 开发经验不等于已经掌握模型数学原理；反过来，学习模型原理也不自动等于掌握 AI 系统工程。

### 当前学习主线

- 贯通“严格数学对象—模型结构—训练过程—推理—完整 GPT 系统”；
- 理解上下文、记忆、检索、工具、子 Agent 和外部状态各自解决的问题；
- 把 AI 协作开发文档写成模型可以执行、验证和验收的规格；
- 学习怎样通过结构化上下文、反馈闭环和确定性校验提高 AI 工作质量。

## 2. 画像更新规则

用户说明已经理解某个模型概念、完成某一学习阶段、仍不理解某个环节或把学习目标转向新的 AI 方向时，在同一轮更新本节并修改日期。不要因为用户已经实现 Agent、Skill 或记忆系统，就把张量、损失函数、注意力等模型原理标为已掌握。

## 3. 模型与算法原理

按技术依赖关系组织，不按流行术语或历史时间简单罗列。每个核心概念尽量说明：

- 它解决什么问题；
- 严格数学定义；
- 符号、矩阵或张量形状；
- 公式的直观含义；
- 逐步推导；
- 训练或推理时怎样计算；
- 在 GPT 中的具体作用；
- 上游依赖、下游结果与失效条件。

介绍张量、Softmax、交叉熵、注意力、位置编码或反向传播时，从必要先修开始，不只给名称、代码或类比。关键公式先放入完整定义或命题，再解释含义与对象，最后推导。

## 4. AI 系统与人机协作

围绕一次真实任务说明：

- 人和模型各自负责什么；
- 上下文、记忆、检索、工具与外部状态怎样流动；
- 模型输出中的不确定性怎样验证；
- Agent 或 Skill 的触发、边界与失败恢复；
- 哪些步骤需要确定性程序，哪些适合模型判断；
- 怎样留下可检查的中间产物和验收证据。

不要把“写更长提示词”当作完整方法。优先解释信息结构、状态管理、反馈闭环和验证机制。

## 5. Agent、Skill 与记忆系统

至少区分：

- 规则与能力说明；
- 当前会话上下文；
- 持久记忆或知识库；
- 检索与召回；
- 工具调用和外部副作用；
- 子 Agent 的上下文隔离与结果汇总；
- 失败、权限和人工确认边界。

说明每一层解决的具体问题，以及它们为什么不能彼此替代。涉及现有产品或框架时，区分已核验事实、合理推断和设计建议。

## 6. 面向 AI 的项目规格

当主题是“怎样让 AI 按文档生成完整项目”时，根据规模覆盖：

- 目标、用户、成功标准和非目标；
- 约束、运行环境和依赖；
- 系统边界、模块职责和目录结构；
- 接口、数据模型、状态和不变量；
- 正常流程、异常流程和权限边界；
- 关键设计取舍与禁止事项；
- 测试策略、验收用例和完成定义；
- 实施顺序、可并行部分和需要用户决定的阻塞项。

不要把尚未决定的设计写成已确认事实。每项要求都应落实到代码位置、可观察行为或验收证据。

## 7. 已吸收的个性化反馈

- 张量、交叉熵等概念曾未经确认就使用；今后必须先校准先修并给出严格定义；
- AI 原理文章必须沿技术依赖链连接数学对象、计算过程和 GPT 中的作用；
- AI 系统文章必须讲清组件、信息流、状态、失败边界和验证机制；
- 概念密集文章先交代整体结构，并用贯穿案例承载概念，避免形成术语清单；
- 用户的 Agent 工程经验与模型理论水平要分别维护。

模型、Agent、Skill、记忆、检索与 AI 协作的可复用反馈写入本文件；纯软件工程规则写入计算机 Skill；只针对某个项目或模型版本的修正留在原文章。
